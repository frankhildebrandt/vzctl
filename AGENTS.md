## Learned Workspace Facts

- `vzctl` ist ein CLI-first DevStack-/Hypervisor-Projekt auf Apple Virtualization.framework (Environments as Code für macOS-VMs).
- Privates GitHub-Repo unter `frankhildebrandt`; Planungsdokumente liegen unter `docs/planing/` (Plan, Reviews, Decision Log, Canvas).
- Mindest-macOS-Version ist 26; Pre-26 ist unsupported.
- Prozessmodell: Supervisor plus ein Helper-Prozess pro VM (Helper owns `VZVirtualMachine`); Supervisor owns vmnet-Refs und DNS, Helper nur Attachment-Handles; Guest-Control primär per vsock-Agent (Supervisor `vm.exec`/`vm.agent.*` → Helper-Control-UDS → GuestAgent); Console-/exec-TTY-Attach über UDS unter `helpers/`; Detach mit Ctrl-P Ctrl-Q.
- Repo-Layout: Rust-CLI unter `crates/vzctl`, Swift-Daemon unter `daemon/` (`vz-supervisor`, `vz-helper`); Runtime-State unter `~/Library/Application Support/vzctl/` (UDS + SQLite).
- Internes DNS stellt der Hypervisor bereit (Zone `{vm}.{net}.{project}.vz.test`); Host-Listener `127.0.0.1:15353`, macOS löst über `/etc/resolver` auf; Guest-Nameserver ist Bridge `.0`; auf Custom-vmnet ist Host-Gateway/DNS `.0` (nicht `.1`), Router typisch `.2`, Guests `.10+`; Cross-Net nur über Router-VM.
- Stacks sind deklarativ per Verzeichnis/Git-Repo und `hypernetwork.config.yaml` (`apiVersion: hypernetwork/v1`, Spec `docs/specs/hypernetwork-v1.md`, `vzctl validate`) steuerbar (`plan|diff|up|apply|down|adopt`); `adopt` ist report-only (stale Helper-Locks melden, kein Mutate/Reclaim); Referenzbeispiel `examples/edge-dmz`; VMs ohne explizites Netz landen im konfigurierbaren Default-Netz (shared, voller Egress/NAT); hypernetwork kann optional `cpus`/`memory` durchreichen.
- VMs teilen ein sealed Base-Image (APFS linked clone / clonefile + pro-VM dataDisk); Identity (machine-id, NIC/MAC, SSH-Host-Keys, cloud-init instance-id) wird pro Clone neu gesetzt; Base nie writable öffnen; `vm create` speichert `resources.{cpus,memory_mib}` (Defaults 2/1024), optional `--root-password` per NoCloud cloud-init — keine Default-Passwörter.
- CLI-Contract: `docs/specs/cli-contract-v1.md` (JSON-Envelope, stdout=Daten / stderr=Diagnostics, stabile Exitcodes); VM-Lifecycle/Tools u. a. `vzctl vm list|start|stop|delete|ps|inspect|exec|attach|transfer|services|logs` (IPs in list/ps aus Netz-Attachments; `vm logs`/`inspect.logs.serial` aus Serial-Log; `vm transfer` max. 256 KiB); `vzctl dns status`; `vzctl docker` (SSH-Context `vzctl-{project}`); `vzctl port list` (Host-Forwards 127.0.0.1); interaktives `vm exec -it` braucht Capability `exec_tty`.
- Docker-Role: `roles: [docker]` → SSH-User `vzctl` + Key unter `projects/{project}/docker/`, Label `vzctl.dev/dns-services=docker` → `docker.svc.{project}.vz.test`; `cloudInit` wird mit System-NoCloud gemerged; Port-Forwards via Supervisor-Userspace-Proxy (nicht TCP 2375).
- Guest-Agent-Wire-Contract: `docs/specs/guest-agent-v1.md` (virtio-vsock, length-prefixed JSON, Token-Auth); Token dauerhaft unter `/var/lib/vzctl/agent.token` (nicht `/run` — cloud-init `write_files` nur once-per-instance); bei PTY-exec muss `Ctty` Kind-FD 0 sein (nicht Parent-`pts.Fd()`).
- Base-/Image-Pull zielt auf ARM64 Cloud/Server-Images (nicht Installer-ISOs); Aliases u. a. `ubuntu|debian|alpine|arch|fedora|rocky|alma|opensuse|coreos|flatcar|photon|opensuse-microos|talos-latest` (Contract `docs/images/pull-contract-v1.md`); Workflow `pull → bake → seal`; Bake/Seal nutzen lokales `virt-customize` oder die gepinnte Builder-VM-Appliance (`scripts/build-builder-appliance.sh`, Cache unter `images/builder/`); Builder-Work-Dirs und Unix-Sockets müssen unter macOS `AF_UNIX` `sun_path` (~104 Bytes) bleiben — kurze `/tmp/vzb-{token}`-Pfade und kurze exec-TTY-Namen unter `helpers/` (lange `vzctl-builder-{nanos}`-Pfade brechen Bake).
- G0-Netzwerk-/Entitlement-Spike ist Go (vor P0 abgeschlossen); nur Entitlement `com.apple.security.virtualization` — `com.apple.vm.networking` bei ad-hoc codesign → SIGKILL; Ingress/OIDC/CA gehören zu v0.2, v0.1 ist Alpha.
